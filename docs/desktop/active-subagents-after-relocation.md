# Active native subagents after standalone relocation

October 17, 2026. Installed release 0.43.1 qualifies active native Codex child work against the ordinary Windows installation and its selected PostgreSQL/Supabase runtime. The Windows update, saved-result/navigation checks, new live child steering, and normal desktop cold launch have passed. The broader desktop parity goal remains active.

## What was exercised

The installed 0.43.0 chat interface sent one new parent request through ChatGPT and one through OpenRouter. Each parent created exactly one actual Codex child and ended its own turn while that child continued. Both children were running at the same time. A further message to the ChatGPT parent completed while its child was still working, establishing that the main chat remained usable independently.

The ChatGPT child ran a real Windows command that waited before reading a file in an explicitly selected disposable workspace. The verifier changed that file after the command started. The saved command's actual output contained the new marker, and the child applied guidance submitted through its chat controls. This establishes execution and steering beyond a running indicator.

The OpenRouter child accepted guidance, was cancelled through its child chat, and then received a new follow-up in the same native child thread. That follow-up used the connected file-reading tool with the child's own native identity and returned the changed file contents. Each provider's completed child result triggered an automatic continuation in its corresponding main agent. The parent reports contain the actual child output. A cancelled command without a completion receipt remains distinguishable from a completed command; cancellation status alone does not prove that an operating-system process exited.

All requests have durable identifiers and checkpoints. The initial interface verifier stopped after delivery because it inspected the main transcript before its asynchronous navigation finished. Read-only inspection recovered the completed work without repeating either paid request. The verifier now waits for that transcript and selects the direct disclosure control. Its first result remains preserved separately.

## Navigation correction

Authentication startup previously combined an explicit main-chat address with the last remembered child. A child remembered from another conversation caused an erroneous unavailable-child notice; a child from the same conversation could redirect the main-chat address into that child.

The new resolver gives an explicit main, child, library, or new-chat address precedence over saved navigation. Ordinary startup still restores the last saved location, including a child. Four focused regression cases cover both kinds of remembered-child conflict, child reloads, explicit libraries and new chats, and normal restoration. Installed verification passed the same paths against the original completed child work, including dedicated child navigation and collapsed inline results for both providers.

## Installed qualification and remaining boundaries

The update created and verified a backup of the database and native history before its first installer attempt from the ordinary Windows context. It preserves the selected database binding and encrypted credential store. The old installer and retained source installation/database remain available for recovery.

The first installation attempt failed because the private backup helper loaded the old installed archive and retained its file handle while Squirrel attempted full-install cleanup. The fatal installer log and failed attempt are preserved. After that failure was confirmed, the owned bootstrapper and helper were closed. A corrected helper verified the same recovery backup without loading the old installation, and a separately checkpointed repair installed 0.43.1 successfully. Its delivered archive matches the prepared image, and the credential store and database binding match their values before repair. The credential file's modification time also predates the first installer attempt. Future maintenance helpers must finish their installed-code inspection and release that process before installation, or use independently prepared resources.

After the update, the same saved OpenRouter child accepted one new follow-up and a new steering message while a real Windows command was waiting. The command read a marker written after it started; the child returned that output with the requested steering suffix, and its main agent automatically continued with the result. This separate intentional follow-up has its own recorded turn and checkpoint. No earlier model request was replayed.

All 6,137 installed files match the prepared release, including 997 compiled modules and 45 migrations. After normal application shutdown, the copied runtime also stopped and the retained original stayed stopped. The real desktop shortcut then cold-started one ordinary Windows instance with all six native services and authentication healthy. Both completed children, their reports, and the new steering result remained saved. The test debugging port is closed and its owned shortcuts are disabled. Original navigation, drafts, composer choices, and appearance were restored, and the two verification conversations remain archived.

The final data comparison again preserved both accounts, passwords, roles, all 93 earlier conversations, all 312 earlier messages, and the 45 migration checksums. The two archived test conversations account for the six additional regular messages. Verification added no accounts or database migrations.
