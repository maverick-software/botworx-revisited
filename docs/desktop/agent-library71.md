# Agent document library — source qualification for 0.44.71

The next release adds search, collections, tags, descriptions and editable library names. The agent editor keeps assignment changes separate from library changes. Refresh preserves valid unsaved choices and removes selections whose files were archived or deleted elsewhere. Dirty-state tracking compares the effective saved assignments, so a completed archive does not create an unnecessary unsaved-change warning.

Archiving immediately disables every assignment to the document and revokes existing document-read snapshots. Original bytes, extracted text and file versions remain stored. Restoring makes the document active without assigning it to any agent. The user must select it and save settings to grant access again. The database also rejects direct active assignments to archived or foreign-owned files.

Replacing a file keeps its document identity, display name, collection, tags and assignments. The current original and metadata become a retained previous version. The file version and content hashes change, which invalidates prior native document scopes. Using an older file version creates a new current version and keeps the earlier current file. The dialog lists file names, dates, sizes and whether each original exists. It permits deleting an older version while protecting the current one. Only an archived document managed by desktop storage can be permanently removed here; the explicit confirmation covers its registry, originals, versions and assignment records.

Migration72 adds the broker-only desktop_media_revisions table and human library RPCs. Metadata operations require the expected content version and exact updated timestamp; stale changes fail before mutation. Original/history ownership is checked explicitly. The retained-original budget includes both current files and earlier versions, with a 256 MiB account limit and at most 50 previous versions per document. Restoring an archived document respects the 200-active-document limit. Earlier records without retained originals retain their previous extracted-text metadata; those versions cannot be restored as original files.

The existing settings RPC keeps its public broker name. Document assignments use the account lock shared with import/archive/replace; other settings use the preserved prior implementation through a private fallback. The real database test verifies an identity-settings save through that wrapper and rejection of direct fallback calls. Models still receive only the four scoped document-reading tools; these library mutation operations are human controls.

The management dialog reports failures inside the dialog, retains unsaved details after conflicts, and disables editing while a save is pending. File actions require saving or resetting local details first. Wide/light and 520px/dark layouts were rendered, inspected and checked for overflow. Filters have explicit accessible labels. Reversible archive/restore is immediate; irreversible deletion requires confirmation. Unknown upload/replacement outcomes are refreshed for review and never automatically replayed.
