# Dropped files and pasted screenshots

Introduced in desktop 0.11.0. Drag files or a folder onto the chat, or paste an image into the message field. The composer shows document/folder cards and image thumbnails. Clicking a thumbnail opens a local preview. Remove detaches a source from the draft; Files and folders → Forget removes its saved reference. Original files remain on disk. Forgetting a pasted image deletes its encrypted local copy. Saved messages retain the original context snapshots used for their requests.

Native files use Electron's [File-to-path API in the isolated preload](https://www.electronjs.org/docs/latest/api/web-utils). Paths are checked again in the trusted process, including credential/backend/application exclusions and canonical paths. A failed batch adds no references. File reference changes are serialized per account. The renderer cannot supply an arbitrary path through the attachment bridge by assigning a property to a synthetic File.

Clipboard images have no original filesystem path. The trusted process validates and re-encodes them as PNG, limits image dimensions, and writes each copy under the installation's private Windows profile using Windows-provided encryption. Reference metadata remains account scoped. Account changes during import stop it from becoming a draft attachment for another account; newly written uncommitted copies are removed. On later access, recovery removes encrypted copies left without references by an interrupted import. These images cannot be treated as editable text files by workspace tools.

Supported inputs remain UTF-8 text/code and PNG, JPEG, or WebP images. Each file is limited to 2 MB, including a pasted image after conversion to PNG; each message accepts up to four images and twenty combined file/folder sources, including project context. Folder traversal retains its existing text-file limits and sensitive-path exclusions. Up to 100 references and 40 MB of pasted images can be retained per account. PDF/Office extraction remains further work.

Attaching and previewing are local operations. From 0.43.6, sending a message authorizes its selected attachments under Default permissions, Selected files access, or Full access. Follow-ups can use their saved context without another file-sharing dialog. Chat only blocks submission with draft attachments and excludes earlier file context when continuing without attachments. A model that advertises text-only input rejects image context before inference. Both provider adapters use their required image request format and keep the same saved conversation. No provider is changed automatically on failure.

The database backup includes image snapshots in saved messages. Unsent pasted images belong to the Windows application profile and are retained by ordinary upgrades; they are not exported by the database-only backup. Moving to another Windows account requires reconnecting protected local settings and pasting any unsent images again.

Verification covers atomic batches, duplicate paths, ownership, sharing denial, local previews, malformed/oversized images, interrupted commits, unreferenced-copy cleanup, actual Windows encryption, native-backed file/folder drop, preserved draft text, text-only rejection, Chat-only privacy, both provider payload formats, and saved snapshots after forgetting/reload. Controlled desktop checks use generated images, injected drag/paste events, and simulated inference. Installed recovery and live visual inference are recorded in the implementation status after they complete.

The full source desktop workflow passed recovery of a real encrypted pasted image after forced termination. It also uncovered a project-save race: the folder picker returned before account/path checks finished, while Save remained available. Project selection now keeps its controls busy until the selected reference is ready; a deliberately delayed picker verifies that Save stays disabled. The navigation, attachment, voice, tool, settings, and recovery workflows passed together after this fix.

Live installed verification in 0.11.0 used both real GPT-6.1 Sol connections with High thinking in one conversation. The generated screenshot contained two different codes. ChatGPT returned the first requested code, and OpenRouter independently read the second code from the earlier screenshot. Neither requested answer appeared in the prompt text, and the first reply contained only its own code. Four messages and the original image snapshot reopened after forgetting the local copy. The screenshot was supplied through an injected paste event; no unrelated clipboard contents were read or changed. No inference was simulated. The retained chat is Live screenshot IMAGE-27792F.
The actual installed 0.11.0 application passed the complete desktop regression, including the delayed project picker, native-backed file/folder drop, forged-file-path rejection, pasted previews, text-only model rejection, both image request formats, saved image previews after reload, and recovery of an encrypted image after forced termination. These regression requests used controlled inference; the separate live screenshot conversation used both real providers.
