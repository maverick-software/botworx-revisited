Agentopia’s embedded browser is connected to the native Codex tool path used by both ChatGPT and OpenRouter. Agents can list their conversation’s live tabs, open a page, read page text and element references, fill ordinary text fields, click controls and scroll. New visits ask permission to share page text with the selected AI connection. Default permissions review browser actions; explicitly enabled Full access can operate within an approved site. A newly reached origin requires another sharing review. Chat only and Selected files access disable browser tools. Plan mode exposes page visits and reading while withholding browser actions.

Browser activity uses the existing saved tool receipts and approval controls. Opening an agent tab adds it to the current conversation’s right pane. An already open document stays selected; Open browser tab in the tool activity brings the controlled page forward. Background work in another conversation does not change the current pane. Provider switching retains the same live tab because tabs belong to the Agentopia account and conversation, independently of the model connection.

The implementation uses Electron’s public [Debugger interface](https://www.electronjs.org/docs/latest/api/debugger) and the Chrome DevTools Protocol’s [accessibility tree](https://chromedevtools.github.io/devtools-protocol/tot/Accessibility/) and [input operations](https://chromedevtools.github.io/devtools-protocol/tot/Input/). Remote pages retain their sandbox, separate session, disabled Node.js access and absence of the Agentopia preload bridge. There is no agent-supplied JavaScript execution tool. The few internal element checks run in an isolated browser world. Page text is returned as untrusted reference data.

Snapshots omit current input values, including the child text nodes Chromium creates beneath editable fields. Password, payment, upload, disabled and read-only fields require manual handling. A snapshot returns at most 12,000 text characters and 100 element references, with offsets for further pages. Page text has a one-million-character reading ceiling. Actions reference a particular snapshot and browser node; navigation, another snapshot, a changed target, an overlay, closing a tab or signing out can invalidate those references. Actions are serialized per tab. Account identity, active-agent ownership, conversation ownership and Full access authorization are rechecked before dispatch. A database uniqueness constraint prevents repeated deliveries from dispatching the same request/thread/call again. Browser action text is excluded from generic stored arguments; approved ordinary input remains visible in its review receipt.

An input-dispatched result establishes that browser input was sent. The agent must read the resulting page to establish that the site accepted the operation. Cancellation does not undo input or external effects that have already happened. Interrupted inputs are not replayed automatically. Tabs, snapshots and site grants currently last for the browser session; after restart or renderer reload, an agent needs a newly opened and reviewed tab. Existing manual browser tabs are outside the agent tool scope.

Verification combines actual Chromium operations, database checks and real native inference. `test-agent-browser.mjs` drives a local HTTP page and verifies the server receives the filled text after one click. It covers scoped ownership, input-value privacy, plan/chat restrictions, changed and covered targets, page-modified JavaScript, navigation during review, new-origin sharing, cancellation and closed-tab revocation. Automated receipt tests exercise review, denial, concurrent delivery, native child call separation, input storage and agent revocation.
