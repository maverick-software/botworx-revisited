# Embedded browser dropdown and keyboard controls

Installed private release **0.39.0**, October 17, 2026. ChatGPT and OpenRouter use the same actual Codex 0.163.0 runtime and conversation-owned Agentopia browser tools. PostgreSQL and native Supabase remain the application database and backend.

The new `browser_select` tool chooses exact labels in a native HTML dropdown. It supports one selection, multiple selections and clearing a multi-select. The snapshot exposes native listboxes and option labels. Ambiguous or disabled choices are rejected. Review binds the owning tab, current element, selected state and underlying option values; changing an option value or the user's selection while approval is pending invalidates that review.

The new `browser_press` tool focuses a referenced control and sends one declared key, optionally with Shift. Available keys are Enter, Tab, Escape, the arrows, Home, End, Page Up/Down, Backspace, Delete and Space. Shift uses its complete down/up sequence. Password, payment, file-upload and verification inputs with protected native attributes require manual entry. Read-only fields reject editing keys. The target is checked again after focus so a page cannot silently redirect a prepared key to another input. Key-up cleanup runs after cancellation or a lost acknowledgement. These tools send input to an owned browser document; Windows application input remains a separate capability.

Both operations require a fresh snapshot and pass the existing account, conversation, agent, permission and ownership checks. Plan mode and Chat only do not expose these actions. Default permissions show the proposed input in the chat; explicitly enabled Full access follows the existing approved-site policy. Pending reviews show the website, control name and choices or key in a readable card. Completed activity remains collapsed.

Browser inputs can submit a form or trigger website work. Migration 0043 gives select/key calls unique request/child/provider-call receipts before execution. A repeated or racing delivery cannot dispatch the same call again. An interrupted action invalidates its old references; the caller must inspect the site rather than automatically repeating an uncertain action.

## Boundaries

Direct selection targets native HTML select controls and emits the standard input/change events through isolated DOM operations. Custom menus use the existing click and new keyboard controls. Keyboard requests target one control and one declared key; arbitrary system shortcuts are outside this interface. The browser still needs broader frame/custom-widget coverage, screenshot-coordinate controls and attached-file upload controls.

General Windows mouse/keyboard qualification, native Save dialog interaction, personal Chrome profile consent, clean-machine installation, a full Windows reboot with this release and broader ChatGPT/Codex desktop parity remain open. The overall goal remains active.

Implementation references: [Chromium keyboard event protocol](https://chromedevtools.github.io/devtools-protocol/tot/Input/#method-dispatchKeyEvent), [native selection and input/change semantics](https://playwright.dev/docs/api/class-locator#locator-select-option). These references guide the mechanics; the local Chromium and provider results establish the tested behavior in Agentopia.
