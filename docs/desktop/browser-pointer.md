# Visual browser controls

October 17, 2026 · 0.41.0 installed private release

The shared Codex harness exposes screenshot-based click, hover, drag, and wheel tools for both ChatGPT and OpenRouter. These controls operate on Agentopia browser tabs, including canvas controls whose contents are absent from the document accessibility tree.

A screenshot returns a capture identifier and image dimensions. Inputs use those image pixels. The desktop service converts them to the current browser viewport, including browser zoom, pinch zoom, scrollbars, and reduced-size images. Each capture belongs to one account, conversation, tab, and provider. Navigation, changed viewport, changed target pixels, replaced target nodes, or a changed relevant frame document require a fresh screenshot. Unrelated sibling frame reloads and unrelated animation do not invalidate a stable target.

With default permissions, the chat shows the exact screenshot with a target marker or drag path, readable action details, and Approve/Deny controls. Approval remains disabled until the image loads. Full access follows the existing browser input policy. Known protected fields retain their existing restrictions; local file attachments use the separate reviewed upload tool. Plan mode exposes observation and withholds these input tools.

A capture is consumed before dispatch. PostgreSQL migration 0045 adds unique receipts for these four tools, preventing repeated or racing delivery from dispatching the same provider call twice. If an acknowledgment is lost, the agent must inspect the page before another action. Cancelling a drag releases any held mouse button. Native HTML drag data is supported; operating-system file drag data is rejected in favor of reviewed uploads.

The real Chromium engine test passed single/double/right clicks, rendered hover tooltips, curved canvas gestures, HTML drag-and-drop, two-axis nested scrolling, cross-origin frame clicks, unchanged-pixel frame navigation rejection, ordinary and pinch zoom, reduced screenshot mapping, cancelled-drag release, and lost-acknowledgment protection. The approval UI test passed dark, light and narrow layouts, escaped text, marked image coordinates, loading and expiration behavior, and keyboard denial. These deterministic tests request no model inference.
