# Browser profiles and downloads

October 17, 2026 · Installed private release **0.36.0**

The embedded Agentopia browser now has an account-specific persistent Chromium profile. **Settings → Browser → Keep website sign-ins** is enabled by default. Turning it off clears that account's retained website data and uses a temporary session. **Clear website data** removes cookies, website storage, authentication cache and cached pages for the current Agentopia account, stops its active transfers and reopens browser tabs. It keeps Agentopia accounts, chats, selected files and downloaded files. Other Agentopia accounts and Google Chrome profiles are separate. HTML canvases use another temporary session.

Website data stays in the Windows application profile and is excluded from Agentopia's database/native-session backups. Preferences and download history use the existing Windows-encrypted local store. These are local browser profiles; they do not synchronize website sign-ins to another computer. The session implementation follows Electron's public [persistent partition API](https://www.electronjs.org/docs/latest/api/session#sessionfrompartitionpartition-options).

The browser toolbar and Browser settings open **Downloads**. The list shows the actual saved filename, the initiating website's origin, progress, pause/resume, cancellation and **Show in folder**. A toolbar badge counts active transfers. Every normal download uses Electron's native Save As flow with overwrite confirmation. Agentopia does not supply a final path or automatically open a downloaded file. Default filenames remove Windows-invalid characters and reserved names; a filename explicitly chosen in Save As is retained in history. The list keeps fifty recent entries and allows up to four active transfers, with one pending save choice. Clearing finished history keeps the files. An external move or deletion causes Show in folder to report that the file is unavailable.

Normal app closure, sign-out and renderer reset stop active transfers. An interrupted process leaves a recorded transfer marked Interrupted on the next startup; it is not restarted automatically. Resume applies to a still-live transfer and may restart its network request when its server does not support continuation. Electron documents these behaviors in [DownloadItem](https://www.electronjs.org/docs/latest/api/download-item); the pinned [44.7.2 download delegate](https://github.com/electron/electron/blob/v44.7.2/shell/browser/electron_download_manager_delegate.cc) opens the native dialog when no save path has been supplied.

Both native connection configurations expose `browser_downloads` through the existing declared tool schema. It returns the current conversation's agent-owned download metadata, with no local paths or file contents. Downloads are not attached to a chat automatically; attaching a file supplies its contents through the normal file-sharing controls. These browser controls do not narrow Windows command permissions the owner has separately enabled. Manual tabs and other conversations are excluded from the agent's download-status tool. Chat-only and Selected files permissions disable browser tools. Plan mode retains the read-only download-status tool. Page sharing and browser actions keep their existing approval rules, including for logged-in websites.
