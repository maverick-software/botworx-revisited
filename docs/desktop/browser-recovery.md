# Browser recovery across restarts

Installed private release **0.38.0**, October 17, 2026. The existing PostgreSQL/Supabase database and actual Codex 0.163.0 execution path remain in use for ChatGPT and OpenRouter.

Agent-owned embedded browser tabs now retain their identity, owning account/chat, last address and title in the Windows-protected credential store. URL/title changes are checkpointed; no form values or action sequence are serialized. Website cookies continue to follow the account's Keep website sign-ins preference. The database contains tool receipts; protected local browser state stays outside database backups.

After a full application restart, `browser_list` distinguishes saved tabs from live tabs. `browser_restore` requests fresh page-sharing approval and reloads the saved address under the same logical tab ID. It does not replay clicks, submitted forms or unsent input. Screenshot sharing still requires its own site/provider approval. `browser_close` closes and forgets the tab; closed IDs are excluded from stale workspace saves. Deleting a chat removes its owned browser records. Neither provider is changed automatically.

Switching chats or hiding the workspace keeps active agent tabs running. Explicit tab closure ends the view and its sharing state. The browser also obtains a rendering surface for a background tab, so existing reviewed click/fill tools work without showing or focusing another window. Changing that same tab's layout interrupts an in-flight operation; hiding an unrelated pane does not. Capture warmup retries only the native read-only surface-unavailable result before an action begins.

Settings → Browser → Agent browser tabs lists the saved/open tabs with their site and chat names. Long names and addresses stay on one line; Close and forget removes only the selected tab. Storage errors remain visible and leave the saved record intact. The tab registry has a 16-tab limit per account and bounded closed-ID history.

## Boundaries

Restoration reloads an address and retains website authentication only when its saved preference allows it. It does not reproduce a transient page's full document or continue an interrupted network transaction. A page's own GET behavior still runs when it is restored. Session grants are renewed after restart; the provider receives no page automatically before approval.

This qualification uses controlled localhost websites on this Windows computer. General Windows mouse/keyboard input, native Save dialog interaction, an existing personal Chrome profile's consent, clean-machine installation, a full Windows reboot with this release, embedded-browser coordinate/select/keyboard/upload tools and broader desktop parity still need qualification or implementation. The overall desktop goal remains active.
