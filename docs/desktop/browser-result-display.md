# Compact browser activity

Source follow-up after the frozen 0.44.0 candidate, October 17, 2026. This presentation change is not installed. It does not change provider requests, browser input or permission decisions.

Expanded browser activity previously showed the complete result object as a JSON block. Browser screenshots also put capture metadata and text ahead of their image. The new `BrowserResult` component shows a short outcome, page title and address, with the same existing link back to the browser tab. It follows the slim interface's current font sizes and spacing; the added CSS is scoped to these results.

Page reads show counts of controls, upload fields and embedded documents. Page text and the full technical record have separate closed disclosures and are rendered when opened. Folder/file selections show their root name and a collapsed count; opening the count reveals bounded, scrollable relative file paths and sizes. Screenshots remain visible with their original image-preview control, while metadata and the provider's text content move under Technical result. The technical metadata omits image payloads, whose original images remain available through the preview.

The wording preserves what the tool established. Input was sent to the page; a file selection was made available to it. Neither is described as a completed website submission. Failed and interrupted activity uses an incomplete heading, even when saved data contains an earlier dispatch status. Declined actions remain declined. Download rows use their actual completed, interrupted, paused or pending state. Closed tabs omit the old Open browser tab button; saved and live tabs retain their own exact identities when opened from a listing.

The renderer type check and ten actual interface scenarios pass through the real `ToolTimeline` component. Checks cover initially collapsed records, inspecting exact saved text and metadata, escaping page markup, 100-file disclosure/scrolling, incomplete and declined outcomes, closed-tab navigation, keyboard opening of an existing saved tab, screenshot visibility, download states and the unchanged approval/denial endpoint. Dark 760-pixel and light 360-pixel layouts fit long titles, folder names and addresses without horizontal overflow. Screenshot review confirms the compact narrow layout.

Run `npm run desktop:test:browser-results` for the isolated renderer workflow. Evidence and screenshots are under `.supabase/desktop-browser-results/ui-1792286481152/`. It uses a controlled service boundary and generated result fixtures, with no production database, canonical credentials or live model request. It establishes renderer behavior; installed history restoration and a complete released application workflow remain separate release checks.
