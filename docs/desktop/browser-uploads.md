# Reviewed browser file uploads

Agentopia 0.40.1 provides reviewed file selection for native HTML upload controls in its own browser, including the Windows path correction found during 0.40.0 installation checks. Both ChatGPT and OpenRouter use the same actual Codex 0.163.0 harness and the same reviewed browser tool. This extends the existing browser actions; wider desktop parity remains ongoing.

The browser snapshot lists existing file inputs, including hidden inputs in the main document. The agent identifies a field and selects files from the references attached to the current request. Every selection requires a readable approval showing the website, field, filenames and sizes, even with Full access. A different form destination is shown explicitly. Websites can read or send a selected file immediately, before a separate Submit action.

After approval, Agentopia checks the file contents and permissions again. A changed file, removed reference, changed field or changed page invalidates the operation. The browser receives private temporary copies of the approved bytes, with the original filenames. Neither the source paths nor temporary paths are returned to the agent or website. Folder references can provide regular binary child files; the existing protection for private application, backend and credential paths still applies.

Copies remain available while the browser document is alive, because a website may read a selected file later. Clearing the field removes its current selection; an earlier JavaScript file object may still be readable. Closing the actual tab removes its copies. Hiding the pane or switching chats preserves the tab. Normal application startup removes abandoned copies after a process exit, without replaying uploads. Failed cleanup is visible in browser settings with a retry action. Application backups use an explicit resource list that excludes this temporary upload directory.

Limits are ten files per selection, 20 MiB per file, 40 MiB per selection and 100 MiB or 100 retained operations per account. Directory pickers are unsupported. Inputs created only while a custom native chooser is open, detached controls, and broader frame or shadow-root coverage need further work. File selection and a browser acknowledgement alone do not establish that a remote server accepted the upload.

## Windows path correction

The initial 0.40.0 packaged check wrote the correct file to disk, but Chromium exposed a zero-byte file and its multipart request failed before reaching the local server. A diagnostic comparison reproduced the failure with long ordinary paths while shorter copies remained readable. The Windows Store launch environment expands roaming storage into a longer package-cache location, which made the installed check's copy path exceed the ordinary limit.

The same long files became readable and transferred with identical hashes when passed in Windows' extended-path format. Only the upload staging module changed: it now applies `path.toNamespacedPath` to the private Windows paths returned to Chromium. File names, bytes, reference validation, reviews, quotas, cleanup paths, provider adapters and the harness are preserved. The regression uses a long root and a 240-character Unicode name; an archive comparison confirmed that the other 991 compiled modules matched the interim build.

Diagnostic evidence is under `installed-probe/`; the original installed failure is preserved as `installed/evidence-before-path-fix.json`. The repaired installed build passed the complete upload qualification. Browser coordinates, custom chooser/directory/frame coverage, physical Windows input, native Save interaction, personal Chrome consent and wider desktop qualification remain open.

One disposable diagnostic folder holding controlled proof data remains because automatic approval review rejected its removal with “blocked by policy.” Agentopia's normal staged-upload cleanup passed its separate restart test.
