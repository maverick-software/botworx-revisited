# Inspecting other saved chats

October 18, 2026. Packaged in the verified 0.44.18 candidate; not included in installed 0.44.17. Migration `0060-chat-inspection.sql` is required.

Agents can use `list_chats` to find other conversations by title or agent name, and `read_chat` to inspect their saved messages. Results include actual saved status, timestamps, bounded text pages and message links that open the existing conversation-source pane. Explicit inspection works with automatic project memory disabled. It does not automatically add unrelated conversations to every prompt.

The tools are available with Default and Full permissions, including read-only plan mode. Chat only and Selected files modes exclude them. A named agent's memory policy and explicit tool allowlist also apply. The broker supplies account, request, captured project and native thread identity; model arguments cannot select those identities.

Account ownership, archived-chat exclusion and project isolation apply to both listing and direct reading. An isolated project can inspect only itself, and its chats are excluded from outside requests. Reading the current chat is unnecessary because its history is already provided. Returned text is labelled untrusted reference material. File contents, hidden native reasoning, system/tool messages and tool arguments/results are excluded. Recent public tool labels and statuses are available. Recognizable credential patterns are redacted; arbitrary unlabelled secrets in prose cannot be guaranteed detectable.

Long messages use a message offset plus a character offset. The total text budget is at most 12,000 Unicode code points per call, shared across at most twelve messages. Cursors preserve supplementary characters and allow exact reconstruction of long saved text. Listing applies isolation before counting and paging, so hidden chats do not affect those counts.

Reads are revalidated before returning their results. Completed tool receipts preserve the source IDs and survive runtime recovery. Before later inference, the broker rechecks inspected sources for the current request and retained native thread history. Archiving a source or moving it into an inaccessible project prevents another inference step using that retained context. It cannot retract content already sent to a provider, and saved replies can still quote earlier sources. Switching to a fresh native branch does not reuse the earlier branch's tool history.

Independent native children and completion reports can inspect permitted chats after the parent finishes. They must have an active calling scope. Finished roots, stopped children and unrelated native threads are denied. The native MCP gateway now validates live ownership and cancellation both before and after asynchronous permission checks; a tool request cannot itself mark a completed child as running. Explicitly starting a new child turn remains supported.

Automatic project memory uses the same scoped authorization for native children. A completed parent no longer prevents a running child or report from validating its recalled sources. Restore preparation checks ownership, original project, memory settings and source availability before execution exists. Actual tool calls and inference require an active scope. The old legacy signatures retain their running-parent rules. Disabling project memory continues to revoke subsequent recall access.

## Verification scope

`node scripts/desktop/test-chat-inspection.mjs` compiles backend/renderer and runs focused inspection, agent-policy, native ownership and actual-Codex controlled goal regressions. The provider responses are simulated and unplanned external network access is blocked.

`node scripts/desktop/test-chat-inspection-storage.mjs` restores the verified logical backup into a newly generated PostgreSQL database, brings that copy to schema 59, and applies migration 60. It compares all existing auth/application/vault table rows across migration 60. It exercises ownership, isolation, archival, paging, source revocation, native scope and service-only privileges. It also starts the installed bundled Codex executable and directly calls the real ToolService through its MCP transport against that database copy. These direct calls use no model endpoint or provider credential. The fixture controls the parent/child state for this test; actual model-driven child delegation is a separate acceptance case.

The disposable database is removed. Production remains on schema 59 and installed 0.44.17. Evidence is saved under `.supabase/desktop-chat-inspection/`. Failed attempts remain alongside corrected results; the passing run must be matched to its recorded source hashes when preparing a release.

The current database/transport evidence is `.supabase/desktop-chat-inspection/storage-1792344980162/evidence.json`: eleven check groups pass, including current selected-agent search and pinned summaries, active child/report memory scope, restore staging versus execution, and native transport.
