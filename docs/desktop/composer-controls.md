# Compact composer controls

October 16, 2026 · Windows private release 0.29.2

Project, folder and document chips sit together at the top-left input edge, about 12 pixels from the composer boundary. Labels display at most 20 Unicode characters, including the ellipsis. Each chip is also bounded in width. Full names remain available through hover titles and accessible controls. Image thumbnails keep their previews.

The remove button appears when the chip is hovered or contains keyboard focus, and remains visible on devices without hover. Removing an attached folder or document deselects it for the next message; its saved reference and physical files stay available. Removing the project chip from an existing chat moves that chat outside projects, so future requests use its individual context. The project and saved messages remain intact. Leaving a project from an unsent new chat opens the ordinary home draft; the project draft remains stored in that project. The project context button still opens its settings. Full status details live in the chip title and project settings.

The model button opens a 256-pixel thinking panel, with the current effort, model link, reset control and a stepped slider. The slider follows the selected model's advertised capabilities. Clicking the model opens a separate 280-pixel catalog with ChatGPT/OpenRouter tabs, search, default model, the selected model first, and readable names. Model identifiers remain available to assistive technology and in row titles. Search matches names and identifiers. Selecting a model closes the catalog; unsupported thinking is reset to Auto using the existing capability rules. Provider choices, credentials, model identifiers and execution routing are preserved.

Keyboard users can focus the chip removal controls, enter the model search, return to the thinking slider, and close the popover back to the composer button. The existing verification workflows now use `model-controls.mjs` to follow this two-step interface.

`test-composer-controls.mjs` exercises the real Electron UI without requesting AI inference. It temporarily groups an existing saved chat in a disposable project, verifies chip size/position and hover/focus behavior, removes the project and folder through their actual controls, and confirms that the project and file reference still exist. It checks both real provider catalogs, changes the thinking slider, searches/selects a model, verifies saved options, and checks dark/light themes and keyboard focus return. Its cleanup restores project membership, draft/options, provider selections, appearance and window size.

The responsive `test-chat-layout.mjs` checks remain applicable. Five composer/provider unit checks, TypeScript compilation and the production desktop build passed. The native inference qualification remains the 0.29.0 real-provider run; this UI release does not claim another inference run. Source and installed control evidence is recorded under `.supabase/desktop-composer-controls/`, layout evidence under `.supabase/desktop-chat-layout-v2/`, and installer/resource/preservation checks under `.supabase/desktop-poc/composer-controls/`.
