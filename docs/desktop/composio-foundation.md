## Implemented source behavior

`composio-client.ts` talks only to the fixed Composio backend origin through its current v3.1 API. It supplies the project key in a request header, rejects redirects, bounds streamed responses, filters returned account and auth metadata, and replaces service errors with messages that do not echo credentials. It never automatically retries an external operation whose outcome is uncertain. Explicit instant-account execution is withheld. Discovery fetches schemas and known versions; execution supplies an explicit account, owner identifier, version and structured arguments.

The catalog supports search, category filtering and cursors, including native and custom toolkit names. Category listing follows all its pages and rejects loops. Authentication details keep supported methods and required fields while omitting secret defaults and raw credential payloads. Both JSON Schema and the documented named-parameter schema form are normalized, including tools without arguments.

`composio-connections.ts` binds project setup and connection state to the signed-in Agentopia owner. Its credential-store interface requires encrypted production storage; the existing Windows-encrypted Secrets implementation can satisfy that interface. The current test store is memory only. A stable private namespace derives a separate Composio user for each owner. Setup verifies the project key before saving. Replacing a key disables existing bindings pending verification. Catalog caches are owner/project/query specific and are labelled when returned during a network failure; rejected credentials never silently fall back to cached results.

The connection service checks the toolkit's advertised authentication method and the actual remote auth configuration. It creates a managed configuration where supported, creates a custom non-OAuth configuration for methods such as API keys, or requires an existing custom configuration when further OAuth/client setup is needed. It starts a hosted Connect Link, records a disabled pending binding before opening the browser, and activates it only after checking the returned account's owner, toolkit, configuration, scheme and live status. Provider API keys are collected on the Composio-hosted connection page. Raw provider tokens and account state are excluded from public results.

Connection requests serialize per owner to prevent one concurrent sign-in from overwriting another. Cancellation prevents a subsequently completed external sign-in from silently activating the cancelled local binding. Disconnection disables local use before contacting Composio and leaves it disabled if revocation has an uncertain outcome. Agent assignments are checked against an active-owner callback and rechecked when previously prepared authority is used. Remote expiration, owner changes, credential replacement and assignment changes block use. The default assignment covers owned active agents; restricted assignment can select specific agents or none. The actual broker callback enforcing active ownership is still to be wired.
