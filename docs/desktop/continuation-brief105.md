New-agent drafts have no inherited saved-agent grants. Chat-only previews do not inspect those grants. Selecting a native skill, running a bundled script and calling an external connection remain separate capabilities; this change does not activate them.

The registry still checks actual ownership, active agent, enabled assignments, reviewed package integrity and current package contents. Context validation recaptures that binding before later work. Removed, updated or newly assigned packages invalidate it. The existing package reader rechecks grants around reads, so bytes from a changed package cannot be returned under an older accepted binding. JSON object-key ordering after PostgreSQL storage is handled semantically.

DraftPreviewExecution combines package-reader declarations with the implemented file tools, then intersects them with the unsaved policy using each tool's actual namespace. The broker-only preview token binds the source resource agent. It permits `tools.list_plugin_files` and `tools.read_plugin_file` only with that resource binding and rejects namespace substitution or serialized fake tokens. ToolService uses the bound source agent instead of the preview's virtual conversation identity. Calls and exact retries retain independent preview activity; normal chat tables and normal package reads preserve their existing behavior.
