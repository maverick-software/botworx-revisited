# PDF and Office documents

Desktop 0.12.0 reads PDF, DOCX, XLSX, and PPTX files locally. Attach them through Files and folders or drop them into chat. Click the file icon in an attachment card to open its preview in the right workspace pane. Documents also appear in the folder tree and can be read by the agent's file tool.

The preview shows extracted text, with page/section controls for PDFs, Word files, and presentations and a read-only grid for spreadsheets. Extracted text switches to the full text that was read. Refresh rereads a changed file. The preview is local; it does not send the document to an AI provider. Default permissions still asks before sharing. Selected files access remains read-only, and Chat only excludes document context.

PDF pages retain their page labels. Word body text, tables, headers, footers, notes, and comments are read as sections. Spreadsheet text retains cell addresses, booleans, common date formats, shared/inline strings, cached formula results, and hidden-sheet labels. Formulas are never recalculated; an uncached formula is marked as not calculated. Presentations follow the slide order stored in the file, include table text and speaker notes, and retain slide labels.

Each message stores the exact extracted text and reading limits supplied for that turn. A later edit affects the next read, while earlier message snapshots stay unchanged. The same data and notices go through ChatGPT and OpenRouter. A provider is never changed automatically after a document or inference failure. Native files remain on disk; conversation history retains extracted context rather than an archived copy of every binary file version.

## Limits

Documents can be up to 20 MB each; text files and images keep their existing 2 MB limit. A message accepts twenty combined sources, including project sources, with up to ten PDF/Office documents. A folder can supply documents within its existing hundred-file and context budgets. Unreadable or skipped folder entries are reported.

Text extraction is capped at 160,000 characters across message file context and at 200 sections/pages per document. The preview grid displays up to 100 rows and 30 columns; Extracted text includes other read cell values within the text limit. Partial reads are marked in the preview, saved message, and provider context. Office packages have bounded XML sizes and entry counts. A reader job has a thirty-second limit, a JavaScript heap limit, and a maximum of two active workers. Closing/changing a preview cancels its pending parse. Account changes, cancellation, and shutdown stop their document work. Pausing or completing a goal during preparation prevents a new inference request.

Previews show extracted text and values. They do not reproduce the original page/slide layout, drawings, charts, embedded objects, macros, PDF annotations/unflattened form fields, or tracked deletions. Password-protected PDFs require an unlocked copy. Scanned or image-only PDFs do not receive automatic character recognition; their empty extraction is reported, and direct attachment submission stops with an actionable message. Page images can be attached separately for a model that supports images. Legacy DOC/XLS/PPT files and editing Office/PDF files remain further work.

## Implementation and evidence

The reader is bundled JavaScript and runs in a separate worker. It receives only the selected file bytes, keeps the renderer free of filesystem access, and requires no Python, Office installation, or separately installed PDF viewer. The PDF reader uses [unpdf](https://github.com/unjs/unpdf) with its bundled Mozilla PDF.js build. Office package parts use [fflate](https://github.com/101arrowz/fflate) and [saxes](https://github.com/lddubeau/saxes). External resources and XML custom entities are not loaded. Binary documents cannot pass the text/code write-tool checks.

Interoperability fixtures were generated independently using ReportLab, python-docx, openpyxl, and python-pptx. These Python libraries are used only by the developer fixture generator; repeatable application tests read the saved fixtures and the installed application uses its bundled readers. Automated checks cover extraction, Unicode, dates, cached and uncached formulas, slide order/notes, ownership, sharing denial, partial reads, encrypted/invalid documents, malformed package paths, expansion limits, XML entity rejection, actual worker cancellation, queued/startup cancellation, timeouts, provider context, immutable revisions, and goal cancellation.

The focused source desktop workflow passed PDF pages, Word sections, spreadsheet grids and hidden sheets, slide notes, source/preview toggling, refresh, actual read-only file-tool execution, controlled requests through both providers with High thinking, Chat-only privacy, and saved history. The installed document gate, separate live-provider workflow, and full installed regression also passed.

Agent settings → Capabilities → Read documents configures the original Mistral OCR service. The local selectable-text reader uses file permissions and does not require that external service. Scanned-document OCR remains further work.

The installed 0.12.0 document gate passed from the packaged application archive, with development tools removed from the child application's PATH. In the separate real-provider check, ChatGPT completed read-only file-tool reads of all four formats and returned their fresh verification codes. A test then changed the Word file; OpenRouter completed its own read-only Word-file tool and reported both the new code and the earlier saved code. Both turns used GPT-6.1 Sol with High thinking. Four messages and distinct context snapshots reopened in Live documents DOC-A45A54. Inference and tool reads in that conversation were real.

Final verification retained the two original accounts and password records, both real AI connections, all previous live conversations, and the new document snapshots/tool receipts. The installed code and UI match the verified source build; unpdf 1.9.0, fflate 0.8.3, and saxes 6.0.0 were verified inside the archive. All 51 automated checks and the complete installed workflow passed. The normal profile is open with the document guide and live sample spreadsheet in the right pane.
