## Capture and restoration

External selections previously retained paths into the original Windows profile without carrying their contents. The producer now streams their bytes into a separate compressed archive. Each reference receives a path under an account-owned namespace in Agentopia Files. The index binds its original path, attachment ID, name, type and inventory to the same database manifest as the rest of the backup. Clipboard images, managed public documents and external selections have separate capture paths.

Folder capture includes ordinary hidden project files, Git metadata, dependency files and empty directories. It does not apply the narrower filters used when sharing folder context with a model. The original files are read and independently checked again after archive verification. The final recovery descriptor is published only after all parts succeed. A backup located inside a selected folder, an unavailable selection, changed contents, linked/hard-linked files or directories, redirected paths, application/database storage, duplicate identities or overlapping recovery namespaces cause refusal. Originals are preserved, and incomplete output cannot be mistaken for a complete backup. This is a byte/content and directory-structure copy; complete Windows permission, link, executable-environment or Git-worktree portability is not claimed.

The eleven-resource capability-5 descriptor seals the new archive and index. Launcher and preparation checks reject corruption, missing resources and a descriptor downgraded to an older capability. The actual installed revision-15 launcher and bootstrap refuse capability 5 before restoration. The preparer copies external contents into the new owned public collection, verifies the published bytes and metadata, and records their identity in the same resumable recovery operation. It never opens the source paths recorded in that metadata.

Before database startup, the startup barrier verifies prepared external bytes and ownership metadata. Completed startup permits later file edits while continuing to check the required metadata. After verified sign-in, the broker restores public and external references before returning the identity used to load settings/drafts. Publishing references and the applied marker is atomic. An account change or conflicting existing ID prevents publication; failed publication can retry. An applied marker prevents ordinary reopening from reviving a removed reference or rejecting later user edits against the original backup fingerprint.

Former paths translate lexically into the recovered collection for the same account. An actual assistant file link can therefore open its copied document after the original path is unavailable. Recovered references also retain their path history when included in a subsequent public-reference backup, preserving the original external alias through that next relocation. The history is bounded; invalid or excessive aliases are refused rather than silently discarded.

An archive inventory edge case was corrected during this work: dictionaries now preserve filenames such as `__proto__` as ordinary entries. The selected-folder regression includes that filename and verifies its bytes alongside hidden project metadata and dependencies.
