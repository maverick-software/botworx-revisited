# Connected Google editor opening — 0.44.64

The Google opening implementation delivered in 0.44.64 is retained in installed 0.44.65, whose UI and supporting resources match this delivery apart from version metadata. [Current queued-delivery repair and installation](live-delivery64.md). Real Composio catalog loading, Google sign-in, upload and editor behavior remain unverified until a valid project key and authorized Drive account are connected in protected setup.

The delivered route supports DOCX, XLSX and PPTX through the signed-in Agentopia user's active Google Drive connection in Composio. The user starts it from a chat file's context menu or the formatted document's file menu. One eligible account is used directly; several accounts produce an explicit account choice. A missing connection opens the Composio tab through the existing Customize navigation. No credential is entered in the document dialog.

The application first resolves the owned file link and reads only that authorized regular file. Existing private-path, link, size, reference and account checks remain enforced. It stages an immutable copy of the selected bytes through Composio and then requests conversion to the corresponding Google editor type. The local original is never changed. The storage request receives the file content and content type; the project key is sent only to Composio's fixed API origin. DNS addresses are checked and pinned, redirects are refused and private destinations are blocked.

Before starting cloud creation, Agentopia saves an operation identifier in its encrypted per-user store. The same identifier is written to the Google file's private application properties. Repeated clicks share an active operation. Completed operations retrieve and verify the recorded cloud document before opening it. A lost response or interrupted creation stays recorded and offers **Check existing upload**. The check searches for the saved identifier, requires exactly one matching native Google document and verifies its metadata. Zero results, several results, incomplete searches and invalid metadata do not authorize another creation request.

A changed remote account on the same connection retains the earlier operation and holds opening for review of that account. An edited local file is a separate version. When checking an older cloud copy, the interface labels the source change before the user opens it. Closing the dialog prevents a late reply from changing the current workspace, while the backend retains the operation record.

This route is for explicit user file actions. Agent tools continue through the existing agent assignment, ownership, tool schema and permission checks. It does not add arbitrary local-path upload arguments to agent tools or claim general agent-side local-file staging for every Composio connector.

The operation journal uses a separate `google-documents` setting, leaving the existing Composio connection-state schema readable by older releases. New portable backups include the journal and require recovery capability 11. The JavaScript reader, Python preparer, PowerShell launcher and bundled recovery fingerprints are updated together. A restore retains completed and uncertain operation identifiers. Provider credentials still require their existing protected setup and verification.
