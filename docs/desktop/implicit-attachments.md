# Attached files authorize chat context

October 17, 2026. Version 0.43.6 removes the native “Share file context with your AI provider?” confirmation. Selecting attachments and sending a message authorizes their use with the selected connection. Follow-up messages can use the saved attachment snapshots without another sharing dialog. Project messages include the project's selected sources and instructions under the same behavior.

Removing a file from the composer stops refreshing its contents on later messages. Earlier messages retain their saved snapshots, so their contents can still contribute to the conversation. Chat only excludes file contents from the request and its supplied history. New chats start without the preceding conversation's attachments. Switching providers explicitly preserves the chat's authorized context.

Account ownership, credential and application-directory exclusions, canonical-path checks, format and size limits, cancellation, and image capability checks remain enforced. A website upload, proposed file edit, command, or other agent action continues through its action-specific review. These reviews authorize the action and destination rather than repeating attachment consent.

The reference documentation describes attachments as supplied chat context and project folders as the local project's selected workspace: [ChatGPT context](https://learn.chatgpt.com/docs/use-chatgpt), [projects and folders](https://learn.chatgpt.com/docs/projects?surface=app). The former blanket per-turn confirmation was Agentopia's own implementation.

All 249 regression checks passed. They observed zero native file-sharing dialogs and made no live provider requests.
