## Implemented behavior

Plugins → Composio now defaults to **Connect your Composio account**. Browser OAuth uses the existing local MCP client, callback, token refresh and protected credential store. The owner grant has its own namespace, separate from saved-agent and draft grants. There is no developer-key field on this default route and no hosted Agentopia service or new dependency. A pinned built-in plugin declares the documented shared endpoint and public-client registration. Public metadata confirms the real endpoint's OAuth challenge, S256 support, registration endpoint and offline-access scope; these are discovery observations rather than authenticated acceptance.

The user explicitly assigns agents through the existing plugin registry. Two agents can use the same owner's connection, while a foreign owner, inactive agent, disabled plugin or revoked assignment is refused. Generic MCP discovery preserves the connector's meta-tools for app-name queries such as “Google Drive.” Calls keep schema validation, displayed arguments, current authority checks, protected credential filtering and the existing Chat only/Default/Full access paths. Disconnect removes this Agentopia account's local grant; it does not delete the upstream apps from Composio.

Unsaved agents use the account connection only after the user selects the reviewed Composio app for that draft. Every call still checks the draft's owner, current selection revision and package digest. Migration0084 changes one existing PostgreSQL readiness function to recognize the selected built-in account connector. PostgreSQL checks selection ownership; the local broker checks the current OAuth grant and its fingerprint before dispatch. Imported lookalikes do not receive that exception. Saving assigns the existing plugin rather than copying the account credential into a per-agent record.

The existing REST catalog and API-key connections remain available under **Existing API-key connections**. No legacy account, credential or Google upload journal is migrated or removed. Google editor upload/conversion remains separate work because that workflow still uses the REST service.

## What was tested and what it establishes

The isolated source qualifier compiles the actual backend and renderer. Its50 protocol/permission checks include actual local HTTP OAuth exchanges for registration, callback verification, cancellation, account switching, refresh, reopening and disconnect. Controlled MCP responses exercise the real client, discovery and executor, including two assigned agents, query matching, argument validation and revocation before a prepared call is sent. The Composio transport responses and identities are controlled fixtures; these are not successful sign-ins to a real Composio account.

The rendered Electron checks use the actual React page and broker dispatcher with controlled authentication/database callbacks. They verify the default key-free form, cancellation, sign-in result, explicit assignment, enable/disable, renderer reopening, separate compatibility route, narrow/light layout and disconnect. The retained API-key page has ten additional checks covering its catalog, paging, delayed replies, connection activation, assignment, failed key replacement, reload and theme behavior. Screenshots were inspected. This establishes the implemented interface; it does not establish an installed end-user connection or real external account data.

A separate actual PostgreSQL test starts the existing isolated QA runtime, applies migration0084 inside a transaction and exercises the real readiness function. It accepts the owned selected built-in connector and rejects five cases: another owner, an unselected scope, a disabled plugin, an imported lookalike and a changed package digest. The transaction rolls back, including the temporary function replacement and rows, and the QA runtime stops normally. Ordinary account data is untouched.

Initial failures are retained. The new controlled MCP fixture threw on the client's initial `server/discover` probe; returning the standard unknown-method response allows negotiation to continue. The older UI checker assumed a white outer frame, predating the installed149 blue-gray frame; its expectation now matches the existing theme. The new account controls also use immediate checkbox feedback while waiting for the existing mutation and refresh, restoring authoritative state after an error. Offscreen screenshot capture waits for fonts and paint after a resize. These corrections are confined to the fixture/checker behavior and the observed UI feedback.
