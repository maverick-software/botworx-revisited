# Native tool routing after the OpenRouter stall

Run152 failed after the calculator had returned a completed process with exit code zero. The retained native history contains 96 write_stdin calls, 94 unknown-process errors, and no workspace write_file call. One process-input call carried the proposed receipt's file-writing arguments. Two namespaced browser calls had already succeeded. An earlier calculator call was rejected for an invalid combination of justification and sandbox arguments; the subsequent invocation succeeded. These are distinct observations, and the successful invocation must not be repeated.

The focused offline check uses the same installed Codex executable, frozen compiled client, inference gateway, private MCP transport and workspace tool definitions. A fresh isolated native home receives four scripted responses: an invalid write_stdin for process zero, a correctly namespaced write_file, a correctly namespaced read_file, then a final message. Only a bounded fixture executor handles file calls; it changes no actual files. The ordinary profile is untouched and no provider credential or paid request is used.

The check passes. The actual outgoing catalog contains the workspace write_file schema under mcp__agentopia_host alongside native write_stdin. The invalid-process error appears in the next inference input. The subsequent correctly named write and read each reach the private MCP executor exactly once, and their results reach the next inference request. This establishes that those calls are advertised and correctly routed with the tested response format. It does not establish that OpenRouter or its model will produce that format reliably during a real task.

The original failed run did not record the raw upstream response stream. The remaining boundary to inspect is therefore the provider's function-call output before the native runtime interprets it. A future paid check must use a new, small task, capture only function name/namespace and argument-schema metadata on both sides, impose a short response ceiling, and perform no user-data operations. Do not rewrite transport, silently substitute a different tool, or replay the old request on the basis of this result. Longer OpenRouter autonomy remains unproven.
