# Notification settings and response alerts

October 20, 2026. Notifications is implemented and qualified in source. Installed Agentopia remains the accepted 0.44.48 release; these changes are not installed. The work follows the saved October 19 reference-settings review in [Usage, settings and document comparison](ui-parity-usage-documents.md). A fresh attempt to initialize the supported Windows computer-use entry point still fails with `failed to write kernel assets` and Windows error 3, so a new native reference capture is not claimed.

Settings now has a Notifications page with account-specific Responses and Tasks controls. Choices save immediately. The page disables conflicting changes while saving, restores the acknowledged value after a failed save, and offers Retry if its initial read fails. It supports keyboard operation and narrow light/dark layouts. It explains that Agentopia must be running and signed in, and that Windows notification settings can silence alerts. Email delivery is explicitly unavailable.

Responses covers completed replies, failed/interrupted responses needing inspection, and final goal completion while Agentopia is in the background. Intermediate goal turns, cancelled requests, streaming deltas and child-activity updates do not generate these alerts. Scheduled runs retain their own notification category and important/all/off task policy; a scheduled result does not also produce a response alert. The account Tasks control can silence all task alerts.

The monitor persists each completion receipt before showing an alert. Duplicate or concurrent events and a restarted monitor therefore do not repeat it. Results suppressed while foreground or muted stay suppressed when those choices change. Account checks run again after asynchronous persistence and scheduled-run lookup. Changing accounts or signing out prevents an old account's alert from displaying. Existing alert clicks also recheck the account before exposing a conversation.

Alert clicks bring Agentopia forward and open the related saved conversation through the existing navigation path. That path saves the current draft and workspace edits first. A missing conversation produces an explanation and preserves the current chat. An open agent/chat editor or handoff prevents an alert from discarding unfinished work. Response alerts use a generic title/body and do not copy message text into Windows notification history.

Notification preferences are included in portable recovery through the same owner-scoped allowlist and atomic application used for other saved choices. New backups declare recovery capability 7. The current launcher, bootstrap and Python reader accept it; the qualified 0.44.48 helper refuses it clearly. The Python reader rejects incomplete/non-boolean preference records and refuses a bundle containing these settings if its declared capability has been downgraded. A fresh-profile preparation case stages both notification preferences and document layouts before database startup. Repeated settings restoration respects later user changes.
