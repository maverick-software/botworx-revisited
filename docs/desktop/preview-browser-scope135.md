# Preview browser acceptance

Outcome: Preview draft can open, inspect and operate its own Agentopia browser tabs before saving an agent, using the existing browser engine, reviews, snapshots, selected-file upload checks and retained tabs. Keep the complete parity goal intact. Commands, delegation and persistent memory remain excluded until their own execution paths exist.

Use an explicit optional preview marker in the existing BrowserTabs records and live entries. Normal records without a marker remain ordinary chats. Preview session identifiers are client supplied and can match a normal conversation identifier, so identifier equality alone cannot isolate these scopes. Preserve this marker through cold reload; neither scope may list, read, restore or operate the other's tabs. Main-process manual restoration validates the stored scope and current owned preview session. Normal account and conversation checks remain in place.

Acceptance:

1. Before-Save UI exposes browser availability without requiring unrelated plugin assignments. Chat only and Selected files do not expose browser tools. Default permissions review visits, sharing and input; explicit Full access uses the existing grant. Plan exposes the current read-only browser family.
2. Broker-issued preview execution tokens bind the current snapshot, policy, owner, creation/source and request. Computer Use and file/skill paths retain their existing boundaries. Browser actions and reviews use preview tool/request records and no normal-chat rows.
3. Ordinary and preview tabs with the same identifier remain separate in live and saved ownership. Foreign owners, other preview sessions, stale refs and changed current authority cannot execute. Denied, duplicate or uncertain operations do not repeat input. Stop joins pending review/execution.
4. Reuse existing browser engine evidence for frames, visual actions and selected-file uploads; add focused tests for their preview-scope coupling. Test actual packaged before-Save visits, reads, input review/denial, Full access, Plan, Stop, isolation and cold tab restoration. Then run one new real OAuth task against a generated loopback page with independently observed page state. No external authentication or message is part of this fixture.
5. Deliver the qualified archive and UI through the existing recoverable installation path, preserving accounts, passwords, history and data. No new framework, dependency or database migration. Reuse existing accepted recovery and provider evidence where unchanged.
