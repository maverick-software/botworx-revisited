## Candidate verification and Stop repair

The first packaged Stop experiment found that interrupting a native child ended its model response while its foreground PowerShell command remained alive. The saved command item had no process ID yet, so the existing background-item filter could not stop it. The native thread registry did contain the command's opaque process identity. A diagnostic run demonstrated that cleaning only that child's native thread ended the real process and preserved a concurrently running sibling. The cleanup acknowledgement preceded removal from the registry, requiring confirmation rather than treating acknowledgement as exit.

The repair uses the existing thread-specific cleanup API after interruption, waits for the child's registry to become empty, then marks command indicators stopped and allows the automatic child report. During cleanup the child remains active. A registry failure leaves an explicit error and active state so the interface cannot claim confirmed cancellation. Two regression cases fail against the pre-repair archive and pass with the repair. No operating-system process ID is used to choose a termination target; the recorded generated PID independently verifies exit.

The frozen candidate is `.supabase/desktop-preview-delegation138/1792873969893`. All129 focused checks pass. The actual unmodified packaged application passes seven workflows, including physical command exit while a sibling remains active, live steering with the selected file read, automatic reports, depth/delegation/Plan policy, current-grant revocation and ordinary-table isolation. Cold reopening retains six preview requests, child transcripts, file receipts and reports with zero model or execution replay. These receipts qualify the named candidate workflows; real OAuth verification and installation remain separate gates.

Earlier controlled attempts remain retained. Steering cancels an in-flight generation, so its test follows the accepted steering acknowledgement and the subsequent real read/report. One later observer expected a steering textarea to remain available after the preview completed; saved data established that steering, reading and reporting had completed, and the observer was corrected. Those observer failures did not justify product changes. The successful diagnostic-cleanup run remains explicitly marked as instrumented and cannot qualify the unchanged archive.
