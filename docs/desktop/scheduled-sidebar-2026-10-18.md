# Sidebar agent selection and Scheduled

The persistent @agent chip has been removed from the composer. Agent selection is now at the top of the normal chat sidebar, with descriptions and the current choice marked. It changes the current chat’s agent while preserving the draft and selected provider/model. Selection waits until current work is finished or paused, and the composer stays disabled while the change saves. Explicit typed @ addressing is retained.

Scheduled follows the supplied reference layout: a secondary sidebar titled Scheduled, New task, Upcoming rows with next-run times, search, status filters and Show more. The center has a clock, a concise introduction and six suggested tasks. Weekly and daily suggestions choose matching repeat rules. The Chats icon returns to ordinary chat navigation.

Selecting a task opens its existing conversation or its details if it has no conversation yet. A compact right context card shows the selected schedule, project, saved run results and file sources. It can be collapsed and reopened, and the selection survives reopening as a per-account display preference. The file, folder, browser and canvas workspace is still available.

New and edited tasks use a compact modal. Repeat/time controls are visible immediately. Advanced provides Notifications, Start each run in new chat, and Runs in. A separate disclosure retains the model/thinking picker, agent, project, time zone, missed-run rule, status, permissions, mode and saved file context. Create task explicitly enables a new task; legacy import remains paused until separately enabled. Editing a paused task preserves its paused state.

Pause, resume, manual run, cancellation, uncertain-run review, deletion and opening results use the existing revision-checked host operations. Windows notification choices are saved in the authoritative task and run snapshot. Important updates covers failures and runs needing review; All results also reports successful completion; Off suppresses alerts. Saved per-account receipts avoid duplicate alerts, and reopening seeds prior history without replaying old notifications. These rules do not evaluate the meaning of a successful answer.

Local schedules require Agentopia to remain open, signed in and Windows awake. The new interface does not add an always-on cloud runner.
