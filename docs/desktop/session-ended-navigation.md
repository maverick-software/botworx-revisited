# Return to sign-in when a session ends

Sylvana 0.45.1 extends this transition to definitive web authorization failures, including desktop revocation and suspended membership. Startup, foreground, and periodic verification validate the committed web binding. A rejected or revoked authorization closes account-owned work, computer control, browser sessions, and voice before returning to the single **Continue with Sylvana** screen. Temporary transport failures retain credentials for retry. Allowance refusals retain the login. Generation checks prevent an older verification result from clearing or authorizing a newer session.

The backend correctly refused a navigation save when no local session remained. DesktopApp retained its earlier identity and displayed the navigation error while Settings stayed open. Account state was refreshed at startup and explicit sign-in, without a shared transition for session loss during an ordinary request.

The backend now marks definitive local-session failures separately from provider errors and transport failures. Its existing chat-event channel also reports local SDK sign-out events. The renderer responds by invalidating the authentication generation, closing Settings and account-owned views, clearing the displayed identity, and routing to `/login`. A delayed failed request from an older authentication generation cannot dismiss a later login. Ordinary connection failures remain errors in the current view.

Saved conversations, account settings, provider credentials, and database records are not deleted by this transition. Dirty composer text is retained in memory by account and draft scope, hidden while signed out, and restored and saved when the same account signs back in during that application session. This memory retention does not replace persistent draft recovery across an application shutdown.

Verification covers Electron-wrapped errors, missing local sessions, token rotation and restoration, failed server logout, stale identity checks, and authentication-generation changes. A controlled test mounts the actual DesktopApp, opens AI usage Settings, rejects a navigation save with the session-ended error, and checks that the login screen replaces Settings without the desktop-location banner. It also verifies temporary failures, signing back in, unrelated-owner events, and the latest unsaved composer text. These tests use generated sessions and do not sign out the user's real account or call an AI provider.

The initial navigation repair changed the backend broker, its session-end helper, and the renderer. Its historical evidence remains under `F:/Sylvana/verification/session-end/`. Release 0.45.1 additionally disables local password verification in schema 92 and uses a shared internal activation step for ordinary browser login and restricted upgrade recovery. See [web-only login](web-only-login.md) for the current package and preservation evidence.
