# Storage settings and reviewed cleanup

October 20, 2026. Storage is implemented and qualified in source. Installed Agentopia remains accepted 0.44.48; this page does not claim delivery of the new controls. The work follows the saved October 19 reference review, which identified separate chats, subagents, archived chats and working-copy categories. A fresh native reference capture remains unavailable because the supported computer-use entry point fails before startup with Windows error 3.

The new Settings page shows those four categories, account-scoped search, chat opening, archive/restore, and a review before deletion. Chat-content sizes estimate the serialized saved session, messages, requests and native activity records. Subagent sizes describe their latest saved app state and are already included in the parent chat's estimate. Working-copy sizes measure regular file contents separately. Neither number is presented as exact Windows volume allocation or immediately reclaimed database space. Unmeasurable folders are marked explicitly.

Storage reads all relevant owned conversations in pages rather than relying on the visible history window. Message queries are restricted to those conversation IDs, and request/native queries also require the owner. Child entries are deduplicated by parent conversation and native thread, retaining their latest saved state. Message contents and child transcripts remain in the backend; the page receives titles, counts, status, sizes and fingerprints. Inspection has explicit row, memory, folder-depth, item-count and elapsed-time bounds and reports a limit rather than silently treating incomplete data as a total.

Chat cleanup requires a current review and compares the saved revision again before using the existing owned conversation-delete operation. It removes saved app records and the chat's draft and browser records. Generated files, external projects and native Codex session files remain. The page explains that separation before confirmation. Subagent app records currently require managing the parent chat; independent child-history/native-profile deletion is not offered and is not claimed complete.

Working-copy cleanup accepts only generated copy identities inside the current account's configured output or earlier workspace roots. It does not accept a caller-supplied path. Reviews include file counts, content sizes and up to thirty inventory entries. The backend hashes the complete reviewed files, checks them again before cleanup, and refuses changed files, links, hard links, special files, redirected ancestors and saved file/folder references. It stages the reviewed directory inside the same owned parent, verifies it again, then removes that exact copy. If cleanup fails, it tries to return the remaining directory to its original location and reports any remaining staging folder for inspection. A review belongs to one account, expires after two minutes and can be consumed only once. Restart does not replay it.

The existing maintenance barrier now also checks live commands, pending terminal reservations and interactive sessions. Storage preview/commit pauses new work through that barrier and quiesces idle native workers before inspection. Active agents, children, scheduled execution, queued messages or commands prevent cleanup. A second check after asynchronous account identification closes the window in which an operation could otherwise enter after maintenance began. Account guards are repeated around file inspection and deletion. Current drafts and workspace edits flush before a review or mutation; an unsaved edit failure prevents cleanup.

The full chat-application test found that deleting the current chat initially focused the composer behind Settings. Storage now opens the fresh chat without moving focus behind the settings page and returns focus to its visible list. The regression test demonstrates the failure before the correction and passes afterward. It also verifies that deletion does not resurrect the removed draft or submit a model request.
