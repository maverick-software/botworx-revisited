## Sharing and permissions

An administrator selects **Application windows** from the composer's **+ / Add to chat** menu, explicitly shares up to five windows, and sees compact removable window chips. Restore minimized windows before selecting them. Selection authorizes reading those windows. Screenshot reads do not ask for the same sharing permission again. Default permissions review each mouse or keyboard input; Full access runs enabled input automatically within explicitly shared windows, subject to the agent's current policy. A required review identifies the observed control, shows its screenshot and target, and disables approval when the preview cannot be displayed. Preview images come from the temporary local observation cache and are not duplicated inside approval records.

Chat only and Selected files access revoke the current chat's window grants and cancel their pending input approvals. Removing a window revokes its grant and cancels queued or active operations for that grant. Stop computer use revokes all of the account's shared windows. The registered emergency shortcut is Ctrl+Alt+Backspace; the native helper also checks this chord during input. Sign-out, renderer loss and app shutdown stop computer use. Windows are never closed by these controls.

Grants are bound to the Agentopia account, native window, process ID and exact process start time. They expire across application restarts. Saved conversations retain their original choices and images; renewed access requires explicit sharing. Clearing window context persists across reload, and new chats do not inherit another chat's window grants.

Plan mode exposes window listing and inspection. It withholds input tools. The initial preview excludes elevated, authentication, password-manager, security, terminal, Agentopia, Codex and ChatGPT windows. The selected application's ordinary owned dialogs may be inspected through its grant. The helper validates real foreground focus, window identity, control identity, input bounds, and observed target pixels where coordinate input is used. It releases injected keys/buttons on cancellation. All OS operations share one execution queue.

## Delivery and recovery

The helper uses public Win32 and UI Automation APIs. Its self-contained .NET 10.0.13 Windows x64 runtime is bundled and pinned, including license notices; the installed application needs no separate .NET SDK. Preparing new helper binaries uses a pinned portable Microsoft .NET SDK 10.0.402. `desktop:prepare-computer` builds and records the manifest, and every desktop build verifies it.

Electron captures selected windows through its desktop-capture API. Native metadata accounts for client bounds, window bounds, and Chromium's resize-border crop. The controlled application test compares real painted edges with accessibility coordinates; the observed discrepancies are at most one screenshot pixel. Ambiguous capture geometry is rejected. [Electron capture API](https://www.electronjs.org/docs/latest/api/desktop-capturer/), [Chromium/WebRTC window cropping](https://chromium.googlesource.com/external/webrtc/+/HEAD/modules/desktop_capture/win/window_capture_utils.cc).

After an input is approved while Agentopia is foreground, a short-lived, pinned helper requests Windows' documented foreground permission for the persistent input worker. It verifies the approval host is actually foreground and the recipient is the same helper executable. It does not grant permission to other processes or change foreground-lock settings. Windows can refuse the request; actual target focus remains mandatory before input. [Microsoft foreground handoff](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow), [Foreground restrictions](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow).

PostgreSQL migration 0037 adds a unique receipt per request, native thread and provider call ID. Repeated deliveries reuse their result; racing deliveries cannot dispatch twice. Reusing an identifier for different arguments is refused. A receipt distinguishes input delivery from verified application effects. Interrupted or uncertain input requires fresh inspection and is never automatically repeated.
