# Composio service capabilities

Composio authentication belongs to the account and is managed in Plugins → Composio. Each connected service is a canonical managed plugin package in the existing desktop_plugins table. Its assignments use desktop_agent_plugins. Service package identities include the exact provider toolkit slug and a deterministic connection identifier; a package cannot substitute another endpoint, authentication declaration, or toolkit. Imported packages cannot claim this managed authority.

Saved agents and unsaved creation drafts receive their assigned connected services automatically when their chat permissions allow tools. Chat selection chips do not initialize these services. The backend creates technical MCP transport and router session context as needed. This automatic transport does not require model-driven setup or service authentication inside the conversation. Service authorization and account selection remain explicit actions on the Plugins page.

Agents discover direct service schemas and invoke the reviewed direct tool. The account adapter internally uses the provider management protocol; agents never receive unrestricted management, shell, workbench, or generic multi-execute tools. The selected connected account comes from the protected account store. Ordinary service arguments, such as Gmail user_id="me", retain their original meaning.

Every action requires the current saved or draft grant, global Composio enablement, live account authorization, and selected service account. Delegated saved agents also require every ancestor agent's service grant. Revocation is checked after approval and immediately before the provider action is sent. Native workers are retired when their own or inherited service grant changes. Generic preview children inherit the accepted source set; unsaved previews cannot invoke named agents. Accepted preview snapshots keep their original source ceiling when additional services become available.

The legacy composio-connect package remains the private account transport and global enablement gate. It is hidden from new capability pickers and cannot expose raw management tools, including from retained creation scopes. A complete, explicit read-only connection scan of the published service catalog establishes the legacy conversion snapshot. Catalog revision and completeness are rechecked before the one-time composio-services-v1 receipt is stored. Saved enabled legacy assignments are copied only for services with active accounts in that snapshot. Global disablement and explicit agent/service revocations remain intact. Later authenticated services require an explicit capability assignment. Services with multiple active accounts retain their migrated capability while waiting for the user to select an account.

The catalog and connection scan load in the background. Chat only does not wait for Composio synchronization. An expired Composio account does not block unrelated plugin listing. The existing API-key Composio adapter remains compatible and keeps its ownership and agent restrictions.

## Verification

The focused service and native revocation tests pass 15 checks. These exercise canonical packages for all 1,645 published catalog rows, leading-underscore slugs, automatic saved/draft availability without a chip, Chat only and Plan restrictions, inherited authority, revocation during dispatch, cross-account access, service-management rejection, retained omnibus denial, stale draft rejection, preview delegation denial, scan completeness/revision checks, and nonblocking background synchronization. Five existing preview binding checks also pass. Main-process and renderer TypeScript checks pass.

The migration was applied inside a transaction in the existing isolated QA runtime on PostgreSQL port 60750. Twelve checks passed, including preserved saved grants while globally disabled, explicit revocations, complete-only conversion, future-service opt-in, repeat-sync behavior, account isolation, canonical declarations, creation authorization, and restricted function access. The transaction rolled back, retaining schema 87; the QA stack was stopped normally.

A broader preview regression run has 18 fixture failures on both the accepted 0.44.79 build and this change. Those fixtures lack the host plugin/credential ownership tables and browser metadata already required by 0.44.79. The updated build adds one passing inherited-worker revocation check to that comparison. These baseline failures do not establish a regression or a successful full-suite qualification. No production data writes, live inference, or application installation were performed by this implementation stage.
